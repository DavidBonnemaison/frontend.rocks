## TL;DR

Opening a `<dialog>` via `.showModal()` promotes the element into the engine's Top Layer, outside every `stacking context` and `overflow: hidden`. The rest of the document automatically becomes `inert`.

## Interactive Lab

Compare a React modal using portals and a focus-trap against `<dialog>.showModal()` in `PatternComparatorLab`.

## Under the Hood

1. `dialog.showModal()` appends the element to the `Document` internal `top layer` list, painted after the root [CSS Stacking Context](/concepts/css-stacking-context).
2. The engine generates a `::backdrop` pseudo-element immediately beneath the dialog inside the same Top Layer.
3. Every node outside the dialog is marked `inert`: pointer clicks, text selection, and keyboard tabbing are blocked natively without global listeners.

```html
<dialog id="confirm-modal">
  <p>Delete production index?</p>
  <form method="dialog">
    <button value="cancel">Cancel</button>
    <button value="confirm">Confirm</button>
  </form>
</dialog>
<script>
  document.getElementById('confirm-modal').showModal();
</script>
```

## Problem Genealogy

- **2012 ([React Portals + `z-index: 9999`](/concepts/react-portal-zindex-legacy))**: Moving modals manually to `document.body` to escape `overflow: hidden`, a ceremony that only existed because CSS lacked a real Top Layer.
- **2018 (`focus-trap` + manual `aria-hidden`)**: Fragile JS boilerplate to trap Tab navigation and hide background nodes from screen readers.
- **2022+ (`<dialog>` Baseline)**: Top Layer, `::backdrop`, `inert`, and `Escape` dismissal built directly into the engine.

## Production Pitfalls

- **Calling `.show()` instead of `.showModal()`**: `.show()` activates neither the Top Layer, nor `::backdrop`, nor background inertness, leaving your modal trapped in the same `z-index` swamp you were trying to escape.
- **Exit animations**: `dialog.close()` switches immediately to `display: none`; combine `@starting-style` with `transition-behavior: allow-discrete` to animate exits.
- **When not to use `<dialog>`**: For non-modal tooltips or dropdown menus that do not block the background, use the [Popover API](/concepts/popover-api-light-dismiss) instead.
